# 中文研究报告质量评测

同一个「星桥」既可以指剧团，也可以指卫星。报告把两条讨论放进同一个热点，就会误导读者。这里用预先标注的小样本逐条核对报告，并检查一次排序改动会把哪些内容带进各平台前五条。

## 本地复跑

在仓库根目录运行以下命令。准备好 pytest 后，评测全程离线，无需平台账号、Cookie、模型或 API Key。

```bash
python -m pytest tests/eval -q
```

加上 `-s` 可查看每个场景的指标，追加 `-k launch` 可单跑新品发布案例。PR 的 CI 也会打印逐场景结果。

## 第一轮结果

所有标题、条目 ID 和链接均为**合成样本**，使用保留域名 `example.invalid`；小红书链接里的 `fixture-only` 用于检验 URL 参数是否完整保留。每个样本都固定在北京时间 2026-11-01 00:05，依照现有 CLI 的日期语义，起止日期为 10 月 2 日和 11 月 1 日，含两端。

| 场景 | 前五条中的相关数 / 实际返回数（最多五条） | 导出证据数（日期未知） | 跨平台聚类与来源结果 |
|---|---|---:|---|
| 新品发布 | 微博 1/1，B 站 1/1 | 2（0） | 同一离线语音包的发布与演示聚成一组 |
| 产品对比 | 知乎 5/5，小红书 1/1 | 7（0） | 知乎给出六个候选；鸟类讨论排在前五之外 |
| 同名不同事件 | 抖音 1/1，百度 1/1 | 2（0） | 剧团首演与卫星遥感分别保留 |
| 跨平台转载 | 微信 1/1，头条 1/1 | 2（0） | 头条同源重复稿去重，跨平台两条保留各自链接 |
| 旧闻重新走红 | 百度 2/2，微博 1/1 | 3（1） | 两端边界各保留一条，旧闻与未来条目被排除 |
| 部分来源失效 | B 站 1/1，知乎无结果，小红书超时 | 1（0） | B 站结果可用，另两个平台分别标记 empty、timeout |
| 全空对照 | 百度、微博均为 N/A（返回 0 条） | 0（0） | 两个 empty，无聚类；无数据时不计算相关率 |

这是六组场景及一个全空对照的实测值。它们检验给定输入经过处理后会得到什么结果；线上召回率、平台可用率及最终生成文字是否准确，需要另取真实研究样本核验。

### 这套评测发现了什么

「新品发布」中，微博交回一条输入法消息和一条冬季甜品菜单，适配器给后者的相关性为 0.02。初次在 `f56034576` 回放时，菜单也被写入了研究报告，微博命中 **1/2**。原因是候选数不超过三条时直接返回，绕过了项目既有的 0.1 硬下限。修复后微博命中 **1/1**，B 站的演示和两条证据的关联均保留。小样本中达到 0.1、但低于常规 0.3 门槛的弱相关项仍可保留。[新品样本](../tests/eval/cases/launch.json)

## 如何判分与维护基线

- **引用。** 从 CLI 导出的 JSON 反查同一平台输入，核对 ID、标题或正文、完整 URL。聚类代表链接必须属于该代表项，跨平台引用 ID 与样本标注的直接关联逐项比对。人工抽查结论时，应另记录「原句、引用条目、支持或不支持的摘录」。
- **时间。** 已知日期须在窗口内并与输入一致。未知日期须保留低置信度，单独计数。样本跨越北京时间和 UTC 的日期边界。
- **相关性。** 各平台分别计算前五条的命中数与实际分母，和[基点导出的 ID 列表](../tests/eval/baseline.json)比较。命中数或命中比例下降均触发失败，并列出基线、当前 ID 和被挤掉的相关 ID。基线取自首次回放；已修复的具体问题由样本的保留与排除标注守住。
- **聚类。** 以标注的事件成员 ID 为准，逐组核对，另检查同名事件保持分离。算法自身的相似度分数不参与判分。
- **覆盖与稳定性。** 核对每个请求平台的状态、原始数和导出数。同一输入独立执行两次，比较完整 JSON，仅忽略线程实际耗时。超时样本通过阻塞本地假适配器并触发真实截止时间分支产生。

新增场景时，在 [cases](../tests/eval/cases) 提交可公开的适配器返回条目，先写好相关、保留、排除、分组与来源状态标注，再从对照版本记录各平台的前五条 ID。调整基线的 PR 应列出前后 ID，并说明具体内容为什么值得进入或退出前五。样本中的相关性分值是上游适配器的固定输入，评测会实际执行中文版的归一化、时间过滤、打分、去重、聚类和报告导出。

评测方法参考[原版离线质量评测](https://github.com/mvanhorn/last30days-skill/blob/262391603/docs/reference/eval.md)，中文场景和判分实现以[中文版基点](https://github.com/Jesseovo/last30days-skill-cn/tree/f56034576)为对照。
